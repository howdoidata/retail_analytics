## Story spec

**C-10: Generate the data catalog and gate it in CI** (CAP-13)

> Shared dbt doc blocks for business terms, a script that writes CATALOG.md from the dbt manifest, and a CI
> check that fails on missing descriptions or a stale CATALOG.md (CAP-13).

Decisions in the story spec: catalog text comes only from the dbt manifest; `CATALOG.md` lists every doc
block once as a business term under its own anchor, then sources, staging, intermediate, and mart models,
and seeds, each with its columns in YAML order; wherever a description contains a doc block's text, the
catalog links to the term instead of repeating it; output is byte-identical for the same manifest; the check
names every source, seed, model, or declared column without a description and fails on a missing or stale
`CATALOG.md`; one CI step runs the check; no hosted docs site.

## Change

- PR: batch PR [#7](https://github.com/howdoidata/retail_analytics/pull/7), shared with C-11. C-10 commit: `0548cd8`.
- Added `uv run catalog` (`src/retail_analytics/catalog.py`): runs `dbt parse` with the repo-local profile
  into a temporary target path (or reads `--manifest PATH`) and writes `CATALOG.md` at the repo root: an
  intro, 13 business terms, the six `raw` source tables, 6 staging, 3 intermediate, and 3 mart models, and
  2 seeds, every column with its description. `uv run catalog --check` lists every missing description (every
  declared column, since the manifest only knows columns declared in YAML) and fails on a missing or stale
  `CATALOG.md`. YAML columns matching built columns is enforced by the layer tests (`test_every_node_is_described` in `tests/test_staging.py`, `test_every_intermediate_node_is_described` in `tests/test_core_layers.py`, and each mart test file's `information_schema` check). Tests on a hand-made manifest (`tests/fixtures/catalog/`) cover
  section and node order, column tables, term links (longest block first, a shared term defined once), `|`
  escaping, determinism, each missing-description case, and stale, missing, and current catalogs; one test
  parses the real project and checks the committed `CATALOG.md` is current. CI runs the check after
  `dbt parse`. No description was missing, so no dbt YAML changed.
