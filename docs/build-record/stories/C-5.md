## Story spec

**C-5: Build the dbt staging models that fix the mess (Ch2)** (CAP-5)

> dbt project on DuckDB with one staging model per source CSV fixing M1–M6, the channel-mapping seed, and a dbt test
> per mess item (CAP-5).

Decisions made with Antonio before implementation: staging may read staging only to drop rows whose parent
was dropped (`stg_orders` and `stg_marketing_touches` read `stg_customers`; `stg_order_lines` reads
`stg_orders`), noted in [CONTRIBUTING.md](../../../CONTRIBUTING.md); the story spec stays whole because its
parts are coupled.

## Change

- PR: [#4](https://github.com/howdoidata/retail_analytics/pull/4)
- Added six staging models (`dbt/models/staging/stg_*.sql`) that read the source CSVs as dbt sources and fix
  M1–M6 as described in [data/raw/README.md](../../../data/raw/README.md); the `channels` and
  `channel_labels` seeds (every label, trimmed and lowercased, to one of the seven canonical channels);
  macros for timestamps, dates, and emails; descriptions and doc blocks for every source, seed, model, and
  column; dbt tests per mess item and grain; hand-made fixtures and Python tests
  (`tests/test_staging.py`) that build the project on the fixtures, on broken fixture variants, and on
  seed 42 (all dbt tests pass; 1.65 clean visits per active customer-quarter from staging).
