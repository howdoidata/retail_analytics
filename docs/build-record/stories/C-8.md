> Build record for one story. Convention: [convention.md](../convention.md). Walkthrough: [build record](../README.md).

## Story spec

**C-8: Build the visit funnel mart (Ch3)** (CAP-5)

> fct_visit_funnel_by_channel: signup → visit milestones by channel and cohort month, step rates, and average days
> between steps, with milestones as a dbt variable and the contract's tests (CAP-5).

Decisions in the story spec: long format, one row per channel × cohort month × milestone, with milestone 0
for the signup; the milestone list (0 plus the `milestones` variable, deduplicated and sorted) is generated
as rows in Jinja and cross joined to the grid, so a new milestone adds rows, never columns or queries; the
mart reads only `dim_customers` (its `milestone_dates` map), `int_channel_spend_daily` rolled up to months,
and the `channels` seed; spend sits on the signup row only; no maturity flag or cohort filtering in the mart.

## Change

- PR: batch PR [#6](https://github.com/howdoidata/retail_analytics/pull/6), shared with C-7 and C-9. C-8 commits: `1f091b5` (the model, tests, and AI review fixes) and the commit that
  adds this record.
- Added `fct_visit_funnel_by_channel` in `dbt/models/marts/`: for every channel in the `channels` seed,
  every month from the first to the last month with a sign-up or spend, and every milestone, the customers
  who reached it, the step rate (one `lag` over the milestones), the mean days from the previous milestone,
  and the month's ad spend on the signup row. A `step_rate` doc block; a description for every column;
  grain, not-null, relationships, and `is_simulated` tests plus singular tests (customers reached never
  rises, step rate within 0 to 1, signup-row nulls, days never negative, grid complete, signup-row
  customers and spend equal their inputs). Fixtures shaped like `dim_customers` with milestone dates and
  `int_channel_spend_daily`, loaded by a loader now shared with the sign-ups mart tests
  (`tests/mart_fixtures.py`), with Python tests (`tests/test_funnel_mart.py`) for each case in the story's
  input matrix, a milestone variable override, broken variants (including a broken copy of the mart for each
  singular-test branch), the contract's column order, a description check over every mart, and seed 42.
  On seed 42 every dbt test passes, the mart has 7 × 24 × 6 = 1,008 rows, and signup rows sum to the
  18,735 customers. Paid Social pooled over all cohorts by the contract's roll-up rule (all simulated):
  5,527 sign-ups; 3,659 reach a 1st visit (step rate 0.662, 12.17 days after signup); 1,732 a 2nd (0.473,
  52.14 days); 817 a 3rd (0.472, 56.28 days); 172 a 5th (0.211, 96.84 days); 1 a 10th (0.006, 371 days).

## Review outcome

- **Human decision:** pending; the change has not had human review yet.
- **AI review findings:** three AI review passes (blind, edge cases, verification gaps; the last found no
  gaps) before commit; the accepted fixes are in `1f091b5`.

| Source | Finding | Decision | Reason |
|---|---|---|---|
| AI review | Several singular-test branches were never shown to fail | Accepted | Added a broken-mart case for each branch |
| AI review | The check that every mart model and column is described was lost in a refactor | Accepted | One test now covers every mart |
| AI review | Two test comments claimed per-customer rules but check cohort totals | Accepted | Reworded |
| AI review | A sign-ups CTE was built from the milestone cross join | Accepted | Now built from customers; same output |
| AI review | `step_rate` column text repeated its doc block | Accepted | Kept the doc block and the null rules |
| AI review | Each mart's test suite also built and tested the other mart | Accepted | Each suite now builds only its own mart |
| AI review | A milestone missing from the map would give silent zeros | Rejected | The dimension and the mart read the same variable in one build, and the map keys are tested |
| AI review | The `milestones` variable is not validated | Rejected | Same as C-6: a default exists and bad overrides are unlikely |
| AI review | Rounded average days make roll-ups inexact | Rejected | The contract fixes the columns and the roll-up rule; error at most 0.005 days |
| AI review | No way to filter young cohorts in the mart | Rejected | The contract says the marts add no maturity flag; the dashboard filters |
| AI review | Seed-42 figures printed, not asserted | Rejected | A reported measurement of a deterministic seed, as in C-6 and C-7 |
| AI review | The grid test counts channels and tests hard-code seven | Rejected | Exact-row fixture tests pin the channel set |
| AI review | The fixture loader imports from a test module | Rejected | Same pattern as the existing core-layer tests |
| AI review | Empty inputs make the grid test fail | Rejected | No real path produces empty sources |
| AI review | A missing previous date could drop a customer from the average | Rejected | Milestone dates are tested to fill in order, so a reached milestone always has a previous date |
| AI review | A null signup or spend date would drop rows | Rejected | Both columns have not-null tests upstream |
| AI review | Fixture loader breaks on an empty file or quoted path | Rejected | Test-only helper with fixed fixtures |
