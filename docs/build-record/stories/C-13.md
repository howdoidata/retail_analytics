# C-13: Publish the dashboard on real mart data

> Build record for one story. Convention: [convention.md](../convention.md). Walkthrough: [build record](../README.md).

## Story spec

**C-13: Publish the dashboard on real mart data** (CAP-5)

> Export the three real marts, swap them into the C-3 workbook, and publish to Tableau Public labeled simulated
> (CAP-5).

The story lands in parts. Part 1 (this record so far) is the export, a standalone `uv run export`. Part 2
adds it as the last step of the one-command run and of the CI pipeline, after C-12 merges. Then Antonio
swaps the workbook's sources to the exports and publishes it.

Decisions in the story spec: the export reads the three marts from the DuckDB file `uv run build` writes
(read-only; it never runs dbt) and writes one file per mart per the contract's
[Exports](../../data-contracts.md#exports) rules; each mart's columns, formats, and unique key are written
down once in the module; decimals round half away from zero to the contract's digits with trailing zeros
dropped and never in scientific notation; rows are ordered by the unique key, so the same database always
gives the same bytes; all three marts are read before any file is written, so a missing database, mart, or
column writes nothing.

## Change

- PR: pending batch PR.
- Added `uv run export` (`src/retail_analytics/export.py`, `[project.scripts] export`): reads
  `fct_signups_by_channel`, `fct_visit_funnel_by_channel`, and `fct_customer_cohorts` and writes
  `data/export/<mart>.csv` (UTF-8, comma-delimited, LF, header row in contract column order, ISO dates,
  `true`/`false`, empty cell for null, per-column rounding). `--database` defaults to the build profile's
  file and `--output-dir` to `data/export/`. Python tests (`tests/test_export.py`) cover the cell
  formatter's rounding cases, byte-for-byte exports of a fixture database built with the marts' column types
  (`tests/fixtures/export/`), reruns, columns picked by name, the missing database, mart, and column cases,
  a value whose type no longer fits, headers, formats, keys, and rounding parsed from the contract, and a
  seed-42 end-to-end run. On seed 42 (all simulated) the export writes 56 sign-up, 1,008 funnel, and 252
  cohort rows, the same counts as the marts, and a second run leaves the files byte-identical. Each header
  is identical to the C-3 sample extract's, so the workbook only swaps data, and the check written for the
  C-3 samples (kept outside the repo, like the samples) passes on the real export with no failures. In the
  repo, the tests check every header against the column order in the contract.
- Part 2: `uv run build` ends by running the export. dbt and the export each run in a child process of
  the same interpreter (`python -m dbt.cli.main build …`, then `python -m retail_analytics.export`),
  because dbt-duckdb keeps the database open read-write until the process that ran dbt exits, and DuckDB
  refuses the export's read-only open until then. A dbt failure exits 1 and skips the export; an export
  failure exits with the export's code. CI runs `uv run export` once
  more after the build and diffs the two sets of files, which checks the console script and that the bytes
  don't change. Tests cover the call order, the skipped export, the export's exit code, and the module entry
  point. `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, `data/export/README.md`, and the walkthrough now
  describe the export as the build's last step.

## Review outcome

- **Human decision:** none yet. Antonio reviews at the batch PR.
- **AI review findings:** one AI review pass (blind, edge cases, verification gaps) before commit; the
  accepted fixes are in the part 1 commit. Part 2 was checked before commit with a real `uv run build` and the
  CI export step run locally; both findings below were fixed in the part 2 commit.

| Source | Finding | Decision | Reason |
|---|---|---|---|
| AI review | Every failure said to run `uv run build`, even when another process holds the database | Accepted | The hint now matches the cause: missing input, locked file, or a changed column type |
| AI review | Duplicate keys (left by a failed dbt test) would make the row order, and so the bytes, vary | Accepted | Rows now sort by the key, then the other columns |
| AI review | The no-flag defaults (database and output folder) were never exercised | Accepted | Test runs the command with no flags and no environment variable |
| AI review | No test for an unreadable database, the `export` script entry, `false`, quoting, non-ASCII text, or several problems at once | Accepted | Tests added |
| AI review | The module docstring credited the contract with this command's own choices | Accepted | Docstring separates the contract's rules from the command's |
| AI review | Fixture CSVs would turn CRLF under `core.autocrlf` | Accepted | `.gitattributes` keeps them LF, as for `CATALOG.md` |
| AI review | NaN, infinity, or overflow in a decimal column | Rejected | The marts' columns are fixed-point decimals, pinned by the mart tests, which hold none of these |
| AI review | A failed write could leave old and new files side by side | Rejected | Rare and loud; atomic writes add code for no seen failure |
| AI review | An empty mart exports a header-only file | Rejected | The generator always yields 10,000+ customers; an empty export is faithful |
| AI review | The command is not listed in the agent guide, README, or contributing guide | Rejected | Deferred to part 2, which changes those files (the README and contributing guide belong to C-12 first) |
| AI review | The seed-42 test adds one more full build to the suite | Rejected | Same pattern as each mart's tests; sharing one build means editing other test files |
| AI review | `export` is also a shell builtin | Rejected | The command name is set by the plan and always run as `uv run export` |
| AI review (part 2) | With the export in a child process, the build still failed: the build process kept dbt-duckdb's lock and the export could not open the database | Accepted | dbt now runs in its own child process too, so the lock is gone before the export starts |
| AI review (part 2) | The CI step copied only the CSVs, so `diff -r` flagged the tracked `data/export/README.md` and would fail every run | Accepted | The step copies the whole folder before the second export |
