# C-9: Build the customer cohorts mart (Ch3)

> Build record for one story. Convention: [convention.md](../convention.md). Walkthrough: [build record](../README.md).

## Story spec

**C-9: Build the customer cohorts mart (Ch3)** (CAP-5)

> fct_customer_cohorts: signup quarter × quarters since signup × channel with active rate, visits per active
> customer, and average order, with the horizon as a dbt variable and the contract's tests (CAP-5).

Decisions in the story spec: long format, one row per channel × cohort quarter × quarters since signup, with
offsets 0 to the `cohort_horizon_quarters` variable (default 7) generated once as rows, so changing the
horizon adds or removes rows, never columns or queries; offsets are calendar quarters from the signup
quarter; the grid stops at the quarter the data ends (the latest signup or visit date); visits after the
horizon are not counted; the mart reads only `dim_customers`, `int_customer_visits`, and the `channels`
seed; no maturity flag.

## Change

- PR: batch PR [#6](https://github.com/howdoidata/retail_analytics/pull/6), shared with C-7 and C-8. C-9 commits: `a280562` (the model, tests, and AI review fixes) and the commit that adds this record.
- Added `fct_customer_cohorts` in `dbt/models/marts/`: for every channel in the `channels` seed, every
  quarter from the first to the last quarter with a sign-up, and every offset up to the horizon whose quarter
  is not after the data end, the cohort size, active customers, active rate, visits, visits per active
  customer, revenue, and average order (visits aggregated once by channel, cohort quarter, and offset, then
  left joined to the grid). `cohort` and `active_customer` doc blocks; a description for every column;
  grain, not-null, relationships, and `is_simulated` tests plus singular tests (active customers within a
  constant cohort size, active rate within 0 to 1, no rows after the data ends, grid exactly complete,
  offset-0 customers and in-horizon visits and revenue equal their inputs). Fixtures shaped like
  `dim_customers` and `int_customer_visits`; the shared loader (`tests/mart_fixtures.py`) now loads only the
  fixture files a folder has and skips the spend pre-step without a spend fixture. Python tests
  (`tests/test_cohorts_mart.py`) cover each case in the story's input matrix, horizon overrides (1 and 2),
  broken fixtures and a broken copy of the mart for each singular-test branch, the contract's column order,
  a description check over every mart, and seed 42. On seed 42 every dbt test passes and the mart has
  7 × 36 = 252 rows (eight cohort quarters, 2024 Q1 to 2025 Q4). Paid Social 2024 Q1 cohort (all
  simulated): 465 customers; active rate by quarters since signup 0.583, 0.267, 0.114, 0.056, 0.024,
  0.022, 0.009, 0.002 (offsets 0 to 7).

## Review outcome

- **Human decision:** pending; the change has not had human review yet.
- **AI review findings:** one AI review pass (blind, edge cases, verification gaps) before commit; the
  accepted fixes are in `a280562`.

| Source | Finding | Decision | Reason |
|---|---|---|---|
| AI review | The visit part of the data-end rule was never exercised by a test | Accepted | Added a fixture case with a visit after the last sign-up quarter |
| AI review | The `active_customer` roll-up text would sum across offsets | Accepted | Now says to sum across cohorts at one quarters since signup |
| AI review | Nothing warned that the data-end quarter may be partial | Accepted | One sentence in the model description |
| AI review | No test that each rate is null exactly when its denominator is 0 | Accepted | Rate test extended; a broken-mart case for each branch |
| AI review | Visits before signup would be dropped or miscounted | Rejected | An upstream test fails any visit before signup |
| AI review | Visits by unknown customers would vanish from mart and totals test | Rejected | Visits have a relationships test to customers upstream |
| AI review | The horizon variable is not validated | Rejected | Same as C-6 and C-8: a default exists and bad overrides are unlikely |
| AI review | Tests derive the data end differently from the model | Rejected | Independent derivation is the point of the tests |
| AI review | The seed-42 test hard-codes seven channels and the horizon | Rejected | Same as C-8: a seed or default change is meant to update tests |
| AI review | The fixture loader skips missing fixture files quietly | Rejected | A missing parent still fails the build as a missing table |
| AI review | No enforced dbt contract with column types | Rejected | Types are pinned by Python tests, as in C-7 and C-8 |
| AI review | Fixtures lack null channels, a gap quarter, a visit past the horizon | Rejected | Nulls are tested upstream; the fixture has a gap quarter; a horizon-1 case covers the rest |
