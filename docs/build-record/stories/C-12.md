# C-12: Run the full pipeline in CI

> Build record for one story. Convention: [convention.md](../convention.md). Walkthrough: [build record](../README.md).

## Story spec

**C-12: Run the full pipeline in CI** (CAP-5)

> CI generates the CSVs, builds all dbt layers on DuckDB, and runs all Python and dbt tests on every change; the
> README documents the one-command local run (CAP-5).

Decisions in the story spec: `uv run build [--seed N]` becomes the one-command run, reusing the generator's
CLI to write the CSVs to `data/raw/` (seed 42 by default) and then running `dbt build` with the repo-local
profile; it exits non-zero when dbt fails, and a generator error stops it before dbt; `uv run generate`
stays the CSVs-only command; CI appends `uv run generate` (the console script) and `uv run build` with no
`--vars`, so the default source folder is the one read, and keeps its triggers, job id, and job name;
offline Python tests guard the default source folder, every console script, and the build order with stubs,
with no extra full dbt build inside the tests; the README quick start lists the prerequisites, the one
command, `--seed N`, and the developer checks; no export step (C-13) and no measured facts (C-14).

## Change

- PR: batch PR [#8](https://github.com/howdoidata/retail_analytics/pull/8), shared with the C-10 and
  C-11 Done moves. Commit `df37c74`.
- `uv run build` (`src/retail_analytics/cli.py`) now takes `--seed N` (default 42), writes the six source
  CSVs to `data/raw/` through the generator's CLI (same summary as `uv run generate`), then runs `dbt build`
  from the repo root with the repo-local profile, exiting 1 when any dbt node fails. CI
  (`.github/workflows/ci.yml`) runs `uv run generate`, then `uv run build`, after the data catalog check.
  New tests in `tests/test_project_foundation.py`: dbt's default `raw_data_dir` equals the generator's
  output folder relative to the repo root; every `[project.scripts]` entry loads; and, with the generator and
  dbt stubbed, `build` generates before dbt runs from the repo root, passes the default or given seed, reads
  the command line when run as a console script, exits 1 when dbt fails, and skips dbt when the generator
  raises. The README quick start now gives the prerequisites, the one command and what it writes, `--seed N`,
  where the marts land, that each run rewrites `data/raw/` (and how to build the CSVs in place), and the
  developer checks; the repo layout lists `cli.py`, `catalog.py`, and the DuckDB file. `CONTRIBUTING.md`
  (setup and CI line), `AGENTS.md` (build line), `data/raw/README.md`, and the walkthrough's Verification
  stage say the same. Added the
  C-12 row to the story index. No model, test SQL, `dbt_project.yml`, or profile changed.
- Resolves two review findings deferred to C-12: C-4's "The `generate` console script is never run in CI"
  ([C-4](C-4.md)), by the CI generate step plus the console-script test, and C-5's "The default raw-data
  folder used by `uv run build` is never exercised by a test" ([C-5](C-5.md)), by the CI build with no
  `--vars` plus the `raw_data_dir` test.
- Verified from a fresh clone with no `data/` outputs or environment: `uv run build` (seed 42) exited 0 with
  all 132 dbt nodes passing (2 seeds, 12 models, 118 tests). The synthetic DuckDB holds 18,735 customers in
  `intermediate.dim_customers`, sign-ups in all eight quarters of 2024 and 2025 in `fct_signups_by_channel`,
  and 1.65 visits per active customer-quarter: 43,589 visits in `intermediate.int_customer_visits` over
  26,348 distinct customer and quarter pairs, the volume in the data contract.
- `uv run build --seed 7` from a fresh clone also exited 0 with all 132 dbt nodes passing (18,556
  customers, sign-ups in all eight quarters, 1.65 visits per active customer-quarter).
